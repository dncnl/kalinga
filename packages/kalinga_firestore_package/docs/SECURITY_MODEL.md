# Security and Privacy Model

## Default posture

1. Firebase Authentication identifies the user.
2. The Flutter application calls the Node.js/Express API for every mutation.
3. The API verifies the Firebase ID token, membership, assignment, consent, purpose, and record state.
4. The API validates the payload against the collection contract before using the Firebase Admin SDK.
5. The Admin SDK bypasses Firestore Security Rules, so server authorization is mandatory and must be covered by API tests.
6. Firestore client access is read-only and fails closed for unmodeled paths.
7. Sensitive Cloud Storage files are accessed through short-lived signed URLs generated by the backend.

## Principal boundaries

- **Caregiver-private:** wellbeing, labor concerns, confidential support messages, support attachments, and personal data requests.
- **Household-shared:** care recipients, observations intentionally shared, instructions, tasks, medications, measurements, handovers, and reports.
- **Partner-scoped:** organization access exists only through an active link and explicit access grant/consent.
- **Platform-only:** AI prompts, model policies, processing jobs, notification outbox, idempotency locks, migrations, and full audit logs.


## Reference-content read policy

- `supportedLocales` is public so onboarding can display language capabilities before sign-in.
- `governmentServices` is public only when a record is both `verified` and `enabled`; drafts and `requiresPreLaunchVerification` records are not publicly readable.
- Approved emergency phrasebooks, terminology glossaries, knowledge articles, training modules, lessons, and safety-rule-set metadata require an authenticated user.
- Individual deterministic safety rules, prompts, and model policies are platform-only/server-side.
- All reference-content writes remain server-only.

## Required backend checks

Every domain endpoint must verify: authenticated UID; active account; active household membership; role and permission; recipient assignment when applicable; field-level ownership; consent and visibility; idempotency key; expected document version; retention/deletion state; and audit logging.

## Key-management and secrets

Do not store service-account JSON, AI API keys, encryption keys, or signing secrets in Firestore documents, the Flutter bundle, Git, or the import seed. Use Google Secret Manager or equivalent server-side secret storage.

## Production decisions still requiring legal/domain approval

- Taiwan-specific personal-data retention periods and deletion exceptions.
- Whether health records are treated as special/sensitive personal data under the final operating model.
- Clinical review of care-plan threshold templates and emergency language.
- Contracts and data-processing agreements with AI providers and pilot partners.
- Which records a clinician or agency may access and for how long.
